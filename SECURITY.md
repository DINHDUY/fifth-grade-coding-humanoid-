# Security Policy

## Supported versions

Security fixes are applied to the latest version on the default branch. Older builds may not receive fixes.

## Reporting a vulnerability

Please do not open a public issue for a security vulnerability. Use GitHub’s private security advisory workflow when enabled, or contact the repository maintainers privately through the security contact configured in the repository settings.

Include:

- A clear description of the issue and its impact.
- Reproduction steps or a minimal proof of concept.
- Affected files, versions, or deployment conditions.
- Any suggested mitigation.

Please avoid including real student data, credentials, device identifiers, or other sensitive information. We will acknowledge reports as soon as practical and coordinate disclosure after a fix or mitigation is available.

## Scope notes

The public app is a static client-side PWA and does not provide a backend or direct robot transport. Reports involving third-party HiWonder services, external links, or vendor software should also be reported to the relevant vendor.
